# Deployment

This project has two different deployment stories:

1. Run the visual builder locally.
2. Publish the static `index.html` generated by the builder.

The builder intentionally does not collect hosting credentials or upload sites automatically.

## Run the builder locally

Development:

```bash
npm install
npm run dev
```

Open `http://localhost:5173`.

Production-style local run:

```bash
npm run build
npm start
```

Open `http://127.0.0.1:3000`.

Configuration can be copied from `.env.example`. Keep `HOST=127.0.0.1` unless you have intentionally secured remote access.

## Test an exported website locally

After export, use the **Preview export** action in the builder or run:

```bash
npx serve exports/your-project-slug
```

The generated `index.html` has no Node.js runtime dependency.

## GitHub Pages

1. Create or open a GitHub repository.
2. Add the generated `index.html` at its root.
3. Commit and push.
4. Open repository **Settings → Pages**.
5. Select **Deploy from a branch**, choose the branch and root folder, and save.
6. Open the published URL displayed by GitHub.

## Netlify

For a manual deploy, open Netlify's new-site flow and drag the exported folder into its supported manual upload area. For continuous deployment, put `index.html` in a Git repository, import it in Netlify, specify no build command, and use the folder containing `index.html` as the publish directory.

## Vercel

1. Push `index.html` to a Git repository.
2. Import the repository in Vercel.
3. Choose **Other** for the framework preset.
4. Leave the build command empty.
5. Use the repository root (or folder containing `index.html`) as output.
6. Deploy and verify the assigned URL.

No framework is needed for this static output.

## Cloudflare Pages

1. Push `index.html` to a Git repository.
2. Open **Workers & Pages → Create → Pages → Connect to Git**.
3. Select the repository.
4. Use no build command.
5. Set the output folder to the folder containing `index.html`.
6. Deploy and verify the Pages URL.

## cPanel / shared hosting

1. Sign in to cPanel.
2. Open **File Manager**.
3. Open the correct `public_html` directory.
4. Back up any existing index file.
5. Upload `index.html`.
6. Upload accompanying assets if a future multi-file export is used.
7. Visit the domain and verify the result.

## Apache or Nginx

Place `index.html` in the configured site document root and ensure the web-server user can read it. The exact path and reload command vary by operating system and server configuration. Preserve any asset folder paths relative to `index.html`.

## Other static hosts

Any service that can serve an HTML file can host the export. Upload `index.html` as the default document. The export does not require PHP, a database, npm, or a server process.

## Contact form note

Static HTML cannot securely deliver email by itself. Configure the Contact Form block with a trusted HTTPS form endpoint before publishing, and review that provider's privacy, abuse-prevention, and spam controls.
